# Лабораторна робота №2 — Варіант 4

Тема: Розробка консольних утиліт для задач кібербезпеки.

Проект містить реалізацію об'єктно-орієнтованої моделі безпечних сесій (`task1.py`) та CLI-утиліти аналізу SSH-журналів `auth.log` для виявлення спроб брутфорсу (`task2.py`).

## Вимоги та встановлення

Для роботи потрібен Python 3.11+. Використовується виключно стандартна бібліотека.
Для контролю якості коду використовується Ruff:

```bash
python -m pip install ruff
python -m ruff check .
python -m ruff format --check .
```

## Структура директорії

```text
labs/lab02/
├── __init__.py

├── task2.py       # Парсер auth.log та виявлення bruteforce
├── main.py        # CLI-точка входу (команди demo та analyze)
├── README.md      # Документація та відповіді на контрольні питання
└── data/
    └── data_v04/
        ├── auth.log           # Навчальний файл логів SSH
        └── blocklist_ips.json # Згенерований звіт з підозрілими IP
```

## Приклади запуску

Всі команди запускаються з кореневої директорії репозиторію:

### 1. Демонстрація ООП (Завдання 1)
```bash
python -m labs.lab02.main demo
```

### 2. Аналіз логів SSH на брутфорс (Завдання 2)
```bash
python -m labs.lab02.main analyze --auth-log labs/lab02/data/data_v04/auth.log
```

Збереження знайдених заблокованих адрес у JSON-файл:
```bash
python -m labs.lab02.main analyze --auth-log labs/lab02/data/data_v04/auth.log --threshold 5 --window-min 5 --output-json labs/lab02/data/data_v04/blocklist_ips.json
```

## Параметри командного рядка (analyze)

| Параметр | Опис |
|---|---|
| `--auth-log` | Обов'язковий шлях до файлу `auth.log` |
| `--threshold` | Поріг невдалих спроб (за замовчуванням: `5`) |
| `--window-min` | Довжина часового вікна у хвилинах (за замовчуванням: `5`) |
| `--output-json` | Необов'язковий шлях до результуючого JSON-звіту |

## Поведінка при помилках

- Неіснуючий файл логу викликає виняток `FileNotFoundError`.
- Від'ємний поріг або некоректний інтервал вікна генерує `ValueError`.
- Рядки логу з невалідними мітками часу пропускаються з фіксацією у журналі `WARNING`.
- Виявлена атака підбору фіксується як повідомлення рівня `ERROR`.

## Відповіді на контрольні питання (Захист роботи)

1. **Інкапсуляція в Python.**  
   Атрибут `_password_hash` є захищеним за домовленістю (protected). Атрибут `__password_hash` (private) задіює механізм Name Mangling: його ім'я автоматично перетворюється на `_ClassName__password_hash`, що запобігає випадковому перевизначенню чи доступу ззовні. У класі `User` хеш та сіль є приватними, а перевірка здійснюється лише через метод `check_password`.

2. **Перевага `@property` для `email`.**  
   Дозволяє звертатися до атрибута та змінювати його через стандартний синтаксис `user.email = "..."`, при цьому автоматично викликається setter з регулярним виразом `re` для валідації формату. Це покращує читабельність та інкапсулює логіку перевірки.

3. **Архітектурні принципи "Is-A" та "Has-A".**  
   - `Admin` наслідує `User`, оскільки виконується принцип "Is-A" (Адміністратор є користувачем, але з додатковими правами).
   - `UserAccount` використовує композицію "Has-A" (Акаунт містить у собі об'єкти `User`, `Session` та `AuditLog`), що забезпечує низьку зв'язаність компонентів і гнучке управління їхніми життєвими циклами.

4. **Методи `__getitem__` та `__setitem__`.**  
   Дозволяють звертатися до полів об'єкта як до елементів словника (`account["user"]`). У класі `UserAccount` вони реалізують захист: дозволяють читати й писати лише визначені публічні поля, блокують прямий доступ до конфіденційних даних пароля, а на невідомі ключі чи типи викидають `KeyError` або `TypeError`.

5. **Декоратор `@dataclass`.**  
   Автоматично генерує спеціальні методи `__init__`, `__repr__`, `__eq__`. Його зручно використовувати для класів-структур даних, таких як `AuditRecord` чи `AuthEvent`, оскільки це скорочує шаблонний код і гарантує незмінність (`frozen=True`) та оптимізацію пам'яті (`slots=True`).

6. **Переваги модуля `pathlib`.**  
   `pathlib.Path` є об'єктно-орієнтованим і кросплатформним інструментом. На відміну від `os.path`, він дозволяє зручно маніпулювати файловою системою через методи самого об'єкта шляху (`read_text`, `is_file`, `mkdir`), уникаючи помилок конкатенації рядків на різних ОС.

7. **Переваги `collections.defaultdict` та `collections.deque`.**  
   `defaultdict` автоматично ініціалізує нові ключі (наприклад, списки або черги для нових IP-адрес) без додаткових перевірок `if key not in dict`. У поєднанні з `deque` це дозволяє ефективно реалізувати ковзне часове вікно зі швидким видаленням застарілих спроб за $O(1)$.

8. **Валідація аргументів в `argparse`.**  
   Параметри `type=Path`, `type=int` та `required=True` дозволяють перевірити коректність типів даних безпосередньо під час розбору аргументів командного рядка, ще до виконання основної бізнес-логіки утиліти, формуючи зрозумілі повідомлення про помилки та довідку `--help`.

9. **Переваги модуля `logging` над `print()`.**  
   `logging` дозволяє розділяти події за рівнями важливості (`DEBUG`, `INFO`, `WARNING`, `ERROR`, `CRITICAL`), додавати мітки часу, автоматично спрямовувати вивід у файли чи зовнішні системи збору логів без зміни коду обробки даних.

10. **Категорії помилок, які виявляє Ruff.**  
    Ruff виявляє порушення стандарту PEP-8 (довжина рядка понад 79 символів, зайві пробіли), невикористані імпорти чи змінні (`F401`, `F841`), застарілий синтаксис типів та некоректний порядок імпортів (`isort`). Усі ці зауваження виправлено, код повністю валідний.
